Повторная активация для обычного запуска не нужна. Почта и самостоятельная регистрация отключены. Описания закрытой установки ниже относятся к первоначальному этапу.

Пакет отделён от статической сборки сайта. Публикация добавила location /forum/ в существующий HTTPS-блок Nginx. DNS, сертификат, статические сборки и ссылки справочника не менялись. Сервисы не перезапускаются автоматически; timer резервного копирования не включён.

Состояние на 2026-11-16: закрытая установка Flarum 2.0.2 завершена штатным CLI-установщиком. Приложение и новая база запущены; HTTP доступен только на `127.0.0.1:8086` сервера, с рабочего компьютера — через SSH-туннель. Русский пакет `flarum-lang/russian:2.0.85` включён. Отправка писем отключена штатным драйвером `null`, самостоятельная регистрация отключена. Публичного адреса у установки нет. Подробности и результаты восстановления — в `docs/server-layout.md` репозитория.

## Оформление закрытого форума

Источники темы: `field-manual.less`, `field-manual-footer.html` и `theme-assets.json` с SHA-256 четырёх локальных шрифтов и двух лицензий. Ресурсы копируются из проверенных исходников основного сайта в assets форума; внешний CDN не нужен. Vendor и готовые CSS не редактируются.

Применение уже подготовленных файлов на сервере:

```sh
cd /mnt/Share/kostya/bronepehota-forum/deployment
python3 forumctl.py check
python3 apply_theme.py
```

Скрипт проверяет закрытый режим, LESS и хеши ресурсов, сохраняет полную копию и снимок шести настроек оформления с цветами тегов в `secrets/theme-before-*.json`, применяет изменения через API и очищает кэш. Временная сессия администратора отзывается после операции. Во время резервного снимка форум кратко недоступен. Письма, регистрацию и права скрипт не меняет.

Возврат к оформлению до первой адаптации:

```sh
python3 apply_theme.py --rollback theme-before-20261116T124426Z-900b282f.json
```

Откат восстанавливает оформление и цвета трёх тегов, сохраняя текущие сообщения и права. Полная копия до первой адаптации — `backups/20261116T124426Z-503dc29c`; её архивы проверены, отдельное восстановление именно этой копии не выполнялось. Снимки и резервные копии с секретами не переносить в репозиторий.

При подготовке темы исправлены права конфигурации внутри образа: PHP ini и Apache vhost читаются UID 33; PHP получает `memory_limit=512M` для компиляции LESS. Это изменения только среды форума. После проверки хранилища образ обновляется командами `docker compose --profile setup build bootstrap` и `docker compose up -d --no-deps --force-recreate app`; bootstrap и установщик повторно не запускать.

## Размещение

Единственный корень постоянных данных — `/mnt/Share/kostya/bronepehota-forum`, отдельная папка на смонтированном ext4-диске `/mnt/Share`. Данные не попадают в `/mnt/Hosting`, `dist/`, репозиторий или офлайн-копию сайта.

```text
bronepehota-forum/               # 0700, владелец kostya
  deployment/                   # этот пакет и локальный .env
  secrets/                      # пароли БД и клиентский файл, 0600
  app/                          # код, composer.lock, config.php, storage, assets
  db/                           # отдельные файлы MariaDB
  composer-cache/               # кэш установки в Share
  backups/<UTC-дата>-<id>/       # SQL, файлы, настройки, manifest SHA-256
  restore-tests/<id>/            # изолированные копии после проверки восстановления
```

Docker использует существующее системное хранилище образов `/var/lib/docker`. Образы, слои сборки и ограниченные Docker-логи не являются резервными копиями. Данные БД и приложения монтируются из Share через bind mounts с `create_host_path: false`; именованных Docker volumes нет. При отсутствии диска Share управляющий скрипт прекращает работу. Запускать Compose напрямую после потери монтирования запрещено; перед каждым ручным запуском выполнять `check`.

Сборка среды использует официальные образы PHP 8.4.27, Composer 2.11.2 и MariaDB 11.8.9, закреплённые по digest. Установщик получает skeleton `flarum/flarum:2.0.0` и фиксирует `flarum/core:2.0.2` и `flarum-lang/russian:2.0.85`. Зависимости расширений разрешаются при первом bootstrap, после чего их точные версии сохраняются в `app/composer.lock` и входят в резервные копии. Повторный bootstrap поверх существующих файлов запрещён.

## Подготовка папок

Скопировать файлы пакета в `deployment/`, не помещая в него секреты из других проектов. На сервере под `kostya`:

```sh
cd /mnt/Share/kostya/bronepehota-forum/deployment
python3 forumctl.py prepare
python3 forumctl.py check
```

`prepare` создаёт отсутствующие папки и случайные пароли, не выводит их и не запускает контейнеры. Для первого запуска существующий корень может содержать только `deployment/`. Права корня должны быть `0700`. Настройки с секретами остаются только на сервере.

## Установка с нуля и закрытый предпросмотр

Эти команды не выполняются самим `prepare`. Перед запуском убедиться, что порт `8086` свободен, и выполнить `check`:

На текущем сервере bootstrap и закрытая установка уже выполнены; повторять их нельзя. Следующие команды относятся к развёртыванию с нуля, а не к обновлению текущего форума.

```sh
python3 forumctl.py check
docker compose --profile setup build bootstrap
docker compose run --rm --no-deps bootstrap
python3 install_private.py
```

Веб-сервер привязан только к `127.0.0.1:8086`. MariaDB не публикует порт и подключена к внутренней Docker-сети. Публичный reverse proxy не создаётся. Для просмотра с рабочего компьютера использовать SSH-туннель:

```sh
ssh -i ~/.ssh/id_ed25519_leonet -p 22 -L 8086:127.0.0.1:8086 kostya@leonet.site
```

Открыть `http://127.0.0.1:8086/`. Для автоматической закрытой установки после bootstrap предусмотрен `python3 install_private.py`: он сохраняет резервную копию, устанавливает русский пакет, создаёт случайный пароль администратора `kostya`, выполняет штатный CLI-установщик и запускает приложение только на loopback. Скрипт отказывается от повторной установки и замены существующих учётных данных. Конфигурация БД: сервер `db`, база и пользователь `forum`; пароль берётся из `secrets/db_password`.

Данные администратора находятся **только на сервере** в `/mnt/Share/kostya/bronepehota-forum/secrets/admin_credentials.json` с правами `0600`. Не копировать файл или пароль в репозиторий, документацию, журнал команд или чат. Для входа использовать имя `kostya`. Обязательное поле email заполнено служебным `kostya@forum.invalid`; это не почтовый ящик. Администратор активирован штатным установщиком, подтверждать адрес письмом не нужно.

Почтовый драйвер `null` не отправляет письма и не записывает их содержимое в почтовый лог; SMTP не настроен. Самостоятельная регистрация отключена настройкой `allow_sign_up=0` и проверена запросом с корректным CSRF: сервер вернул HTTP 403. Восстановление пароля по почте и почтовые уведомления на этом этапе недоступны. До изменения режима почты отдельно согласовать поведение и провести проверку.

В закрытом форуме оставлена одна служебная тема «Проверка закрытой установки» с ответом для проверки работы (`/d/2`). Других участников не создавали. Проверочные API-сессии отозваны.

Сервисы оставлены запущенными для закрытого просмотра; после завершения проверки их можно остановить:

```sh
docker compose stop app db
```

Для последующего запуска уже установленного форума выполнить `python3 forumctl.py check`, затем `docker compose up -d --wait db` и `docker compose up -d app`. Повторно запускать bootstrap или установщик не нужно.

## Разделы и права

Настроены три основных тега в указанном порядке:

| Раздел | Slug | Темы и ответы |
| --- | --- | --- |
| Вопросы по правилам | `rules-questions` | Авторизованные участники создают темы и отвечают. |
| Предложения | `suggestions` | Авторизованные участники создают темы и отвечают. |
| Объявления | `announcements` | Темы создают администратор и модераторы; участники отвечают. |

Разделы читаются гостями, имеющими доступ к закрытому стенду. Во всех разделах гостям запрещены темы и ответы. Нужен ровно один основной тег. Исходный `General` переименован с сохранением ID и существующей темы; её адрес не изменился.

Декларация — `sections.json`; `configure_sections.py` применяет настройки через штатный API, предварительно сохраняет полную копию и ожидает готовности приложения после снимка. При неизвестных дополнительных тегах он прекращает работу, чтобы не менять их порядок. Скрипт использует защищённый серверный файл администратора, не выводит пароль и отзывает только собственную временную сессию. Повторный запуск заново применяет эти настройки и права, поэтому не использовать его как обычную команду запуска форума.

У «Объявлений» включены отдельные права тега. Они воспроизводят действующие глобальные права обсуждений, кроме создания тем и создания без премодерации — эти два действия доступны модераторам и администраторам. Участники сохраняют ответы, реакции и жалобы; права модерации остаются у модераторов. У остальных двух разделов глобальные права не переопределены.

Проверить настоящие политики Flarum без создания пользователей:

```sh
docker compose exec -T --user 33:33 app php < check_sections.php
```

Проверяются просмотр, создание тем и ответы для гостя, участника, модератора и администратора во всех трёх разделах — всего 36 проверок. Фикстуры ролей существуют только в памяти. Почта и регистрация остаются отключёнными. Отдельная форма вопроса и принятие лучшего ответа этим пакетом не добавляются.

## Резервные копии

Для копирования база должна работать. Скрипт запоминает состояние приложения, останавливает его на время копирования и возвращает в прежнее рабочее состояние после завершения, включая ошибку. Если в будущем появятся отдельные scheduler/queue workers, их нужно включить в тот же цикл остановки до публичного запуска. Сейчас такие процессы не настроены.

```sh
python3 forumctl.py backup
python3 forumctl.py verify ИМЯ_ПАПКИ_КОПИИ
python3 forumctl.py restore-test ИМЯ_ПАПКИ_КОПИИ
```

Состав копии:

- `database.sql.gz` — транзакционный дамп с процедурами, событиями и триггерами;
- `app.tar.gz` — все файлы форума, включая конфигурацию, `composer.lock`, аватары и загрузки;
- `deployment.tar.gz` — пакет установки, `.env` и секреты для восстановления;
- `manifest.json` — SHA-256 архивов, версия образа БД и контрольные суммы таблиц.

Каталог копии имеет права `0700`, файлы — `0600`. Архивы содержат секреты и персональные данные будущих участников; их нельзя публиковать или переносить в репозиторий. Архивы не зашифрованы. Незавершённая копия остаётся с префиксом `.pending-`; готовое имя присваивается после проверки всех архивов. Параллельные операции скрипта блокируются lock-файлом. Старые копии автоматически не удаляются.

`restore-test` сначала проверяет SHA-256 и архивы, затем извлекает файлы в новый каталог `restore-tests/<id>/`. Дамп импортируется в отдельный временный контейнер той же версии MariaDB с `--network none` и без портов; контрольные суммы таблиц сверяются с исходной копией. Восстановленный Compose и `.env` **не запускаются**, поскольку указывают на исходное хранилище. Проверочный контейнер удаляется после проверки; файлы остаются в Share для осмотра. Исходная база не перезаписывается.

Это проверка восстановления данных и файлов, не проверка работы интерфейса форума. Возврат рабочей установки из копии выполняется отдельной согласованной операцией: проверить копию, остановить приложение и всех писателей, сохранить текущее состояние, восстановить в новый корень на Share и проверить там до переключения. Автоматической команды перезаписи рабочей базы нет.

Копии на одном физическом диске не защищают от его отказа. Перед публичным запуском нужны согласованные срок хранения, контроль успешных копий и копирование на другой носитель.
