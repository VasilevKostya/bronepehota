# Форум «Бронепехоты»

Решение утверждено пользователем 2026-11-09: GitHub Discussions в публичном репозитории `VasilevKostya/bronepehota`. Сайт остаётся на GitHub Pages. Отдельные сервер, база данных и платные сервисы не нужны.

## Состояние подключения

Discussions включён владельцем 2026-11-09. Публичное чтение и основные категории проверены. Владелец также оставил General и «Голосования»; они сохранены. После входа проверены формат Question / Answer для вопросов и Restricted Announcement для объявлений. Шаблон с кириллическим именем отображался в предпросмотре файла, но не подключался к созданию темы. В проверке та же форма заработала при имени категории Q&A и файле q-a.yml; пользователь согласовал это название 2026-11-09. Подтверждены три русских обязательных поля и стандартный обязательный заголовок. Тестовые обсуждения не отправлялись.

## Настройки GitHub

В [Settings → General](https://github.com/VasilevKostya/bronepehota/settings) в блоке Features включить Discussions. На вкладке Discussions открыть управление категориями кнопкой рядом с Categories.

| Категория | Формат | Назначение |
| --- | --- | --- |
| Q&A — вопросы по правилам | Question and Answer | Разбор игровых ситуаций с возможностью отметить ответ. |
| Предложения по изменениям | Open-ended discussion | Предложения по механике и формулировкам Уральской версии. |
| Объявления и новые редакции | Announcement | Новости и выпуски от владельца/maintainer; участники могут отвечать. |

Q&A сохраняет латинское имя ради подключения формы; стандартные Ideas и Announcements переименованы по таблице, с сохранением соответствующих форматов. Остальные пустые стандартные категории для первой версии не нужны. Уже созданные пользовательские обсуждения сохранять.

Первый модератор — VasilevKostya. Темы и ответы публичны; читать можно без аккаунта, для участия нужен GitHub. Форум требует интернет-соединения и открывается с сайта в новой вкладке.

## Форма вопроса

Файл `.github/DISCUSSION_TEMPLATE/q-a.yml` должен лежать в основной ветке. Его имя должно точно совпадать со slug соответствующей категории. При последующем переименовании категории сверять её ссылку и при необходимости переименовывать файл.

Обязательные поля: версия правил, прямая ссылка на пункт, игровая ситуация и вопрос. Номер версии вводится самим участником: сохранённые копии правил могут отличаться от текущего выпуска. Заголовок темы предоставляет стандартная форма GitHub.

Рабочая форма: [создать вопрос в Q&A](https://github.com/VasilevKostya/bronepehota/discussions/new?category=q-a). После дальнейших изменений проверять русские поля и обязательность заполнения без отправки тестовой темы. Снимок проверенной формы: `output/forum-question-form.png`.

## Принятие изменений

Обсуждение и отмеченный ответ сами по себе не меняют действующие правила. Владелец утверждает изменение, затем обновляет содержание и историю выпусков. Сайт, поиск и PDF собираются из общего источника. Номер редакции правил не увеличивается из-за добавления ссылки на форум.

Модерация выполняется штатными средствами GitHub. В первой версии нет встроенных комментариев под отдельными пунктами, giscus или собственной авторизации. Офлайн-копия сохраняет справочник, поиск и PDF; обсуждения в неё не входят.

## Обслуживание

- При переименовании категории сверять её slug и имя файла формы.
- При смене репозитория обновлять `FORUM` в `scripts/build.py` и ссылки в документации.
- После изменений навигации обновлять `DESIGN.md`, `.impeccable/design.json` и `docs/design/rules-surface.md` в том же наборе изменений.
- Не размещать пароли и токены в коде: обычной внешней ссылке они не нужны.

Документация GitHub: [категории](https://docs.github.com/en/discussions/managing-discussions-for-your-community/managing-categories-for-discussions), [формы категорий](https://docs.github.com/en/discussions/managing-discussions-for-your-community/creating-discussion-category-forms).
