# Автозапуск, копии и ссылки форума

Поручение пользователя от 2026-11-17: запускать опубликованный Flarum после перезагрузки, делать еженедельные резервные копии, направить кнопки «Форум» на `https://bronepehota.leonet.site/forum/`, оставить GitHub только на странице «Редакция и изменения».

## Службы сервера

Подготовлены три системные службы, установка ожидает sudo владельца:

- `bronepehota-forum.service`: после Docker, сети и монтирования `/mnt/Share`; процесс работает как `kostya`, проверяет канонические пути и секреты, запускает БД, ждёт готовности, запускает app и проверяет HTTP. При остановке диска Share служба останавливается. Compose сохраняет `restart: no`, чтобы Docker не запускал базу без проверки диска.
- `bronepehota-forum-backup.service`: тот же проверенный `forumctl.py backup`, от `kostya`, с ограниченным приоритетом диска и тайм-аутом 30 минут. Во время согласованного снимка app кратко останавливается и возвращается в прежнее состояние.
- `bronepehota-forum-backup.timer`: воскресенье, 03:15 `Asia/Yekaterinburg`, `Persistent=true` — пропущенное задание выполняется после следующего запуска. Старые копии не удаляются автоматически.

Установка в SSH-терминале владельца:

```sh
sudo python3 /mnt/Share/kostya/bronepehota-forum/deployment/install_services.py install
```

Установщик проверяет хранилище и unit-файлы, отказывается заменять неизвестные службы, устанавливает только три перечисленных файла в `/etc/systemd/system`, включает и запускает службу/таймер. Пароль sudo вводится только в терминале владельца. Сервер не перезагружается.

Проверка:

```sh
systemctl is-enabled bronepehota-forum.service bronepehota-forum-backup.timer
systemctl status bronepehota-forum.service bronepehota-forum-backup.timer --no-pager
systemctl list-timers bronepehota-forum-backup.timer --no-pager
journalctl -u bronepehota-forum-backup.service -n 40 --no-pager
```

Отключение автозапуска и расписания, с сохранением работающего форума:

```sh
sudo python3 /mnt/Share/kostya/bronepehota-forum/deployment/install_services.py disable
```

Копии остаются в `/mnt/Share/kostya/bronepehota-forum/backups/`: SQL, файлы приложения и пакет обслуживания с секретами, manifest SHA-256. Права папок 0700, файлов 0600. Проверочное восстановление использует отдельный контейнер без сети и не заменяет живую БД. Внешняя копия на другом носителе не настроена.

## Навигация справочника

Исходник `scripts/build.py` задаёт новый адрес для верхнего меню и нижнего меню телефона на правилах, поиске, изменениях, каталоге и карточках. Надпись GitHub у кнопки удалена; доступное имя и подсказка сообщают о сети и новой вкладке. Единственная ссылка на GitHub в пользовательских HTML — «Архив обсуждений на GitHub» на `changes.html`. Старые темы не переносятся и не удаляются.

`scripts/verify.py` проверяет обе навигационные ссылки на всех обычных страницах и отсутствие GitHub вне `changes.html`; старый redirect `armies.html` не имеет меню. Изменения игровых правил и PDF не требуются. Форум не включается в офлайн-копию.

Сайт пока проверяется локально; публикация выполняется обычным единым выпуском обеих площадок по [release-process.md](release-process.md), после подтверждения точного кандидата. Ручная правка dist и отдельная выкладка только главной страницы не используются.

Создана и проверена копия `20261117T085540Z-b970eed4`, восстановление прошло в `restore-tests/c23a393c2c3b` с контрольными суммами таблиц. Живая БД не менялась, после проверки публичный форум вернул HTTP 200. Проверены 45 JavaScript-тестов, 39 Python-тестов (6 пропущены на Windows), 121 HTML-страница, поиск, манифесты и общие тексты сайта/PDF. Начальная проверка меню потребовала учесть старую страницу-переадресацию armies.html; после уточнения проверка прошла. В браузере просмотрены изменения при 1280 px и каталог при 390 px, новые адреса верны и переполнения нет. Локальная офлайн-копия установилась; тесты офлайн-процесса прошли. Эти результаты не заменяют проверку будущего публичного выпуска.
