# Частичные офлайн-обновления

Дата: 2026-11-13. Правила остаются в редакции 0.3.

## Причина изменения

Прежний Service Worker при каждом выпуске скачивал все 761 обязательный ресурс (около 27.8 МБ), хранил их в отдельном кэше и при сбое удалял всю недокачанную сборку. Увеличения каталога также терялись при переключении. Ручная операция имела общий предел 90 секунд, не учитывавший продолжающуюся загрузку.

## Устройство

- Каждая сборка имеет отдельные метаданные со списком обязательных файлов, SHA-256, размерами и маркером готовности.
- Проверенные обязательные файлы хранятся в общем кэше по SHA-256. Новый выпуск с тем же содержимым использует тот же объект без сетевого запроса и без копирования всех файлов в новый кэш.
- В старом формате файл ищется по пути и обязательно сверяется с целевым хешем перед переносом. Подходит и незавершённый старый кэш. Старая копия удаляется только после успешного переключения.
- Увеличения хранятся отдельно, также по хешу. Они загружаются только при просмотре; уже сохранённые увеличения переносятся из старого формата без сетевой загрузки. При ошибке используется малая версия.
- Маркер готовности появляется только после сохранения всех обязательных файлов. До этого активна предыдущая сборка. Неверные данные, промежуточная версия на CDN и ошибки места не подменяют её частичной сборкой.
- При неудаче сохраняются только полностью проверенные файлы. Следующая попытка продолжает с них; оборванный внутри файл загружается заново, HTTP Range для продолжения отдельного файла не используется.
- До шести параллельных загрузок; у файла до трёх попыток. 30-секундный сетевой тайм-аут сбрасывается при поступлении очередного блока тела ответа. Медленная, но продвигающаяся загрузка не прерывается из-за общего времени.
- Проверка обновления имеет отдельный предел 30 секунд; ожидание установки — 120 секунд без прогресса. Увеличение числа готовых файлов или принятых байтов продлевает ожидание. Сообщения других работников и неподвижные heartbeat его не продлевают.
- Уже готовый ожидающий worker применяется без повторного обращения к сети. Переключение ожидает смены контроллера; при неудаче или тайм-ауте 15 секунд обе кнопки вновь доступны.
- При очистке сохраняются текущая и предыдущая полные сборки, а также последняя незавершённая. Их общие файлы не дублируются. Удаляются только больше не используемые хеши этого сайта. При параллельной установке очистка откладывается.
- При нехватке места сначала можно освободить только необязательные увеличения; активная базовая копия не удаляется. Если этого недостаточно, показывается ошибка места.
- После неудачного самого первого сохранения ручная попытка повторяет регистрацию, если прежняя регистрация уже потеряла всех workers.

Принятие обновления остаётся явным: кнопка «Обновить» или ручной запуск через статус. Первая успешная установка становится активной автоматически. При controllerchange открытые страницы перезагружаются по прежнему URL; это не обещание сохранения несохранённых пользовательских форм. В текущем справочнике параметры поиска и фильтров находятся в URL.

## Проверка

Автоматические сценарии находятся в tests/offline.test.mjs и tests/offline-update.test.mjs. Они проверяют разницу файлов, миграцию старого и частичного кэша, повтор после обрыва, несовпадение хеша, смену сборки на сервере, тайм-аут до и после заголовков, медленное поступление тела, нехватку места, увеличения, общий запрос одновременных просмотров, очистку, прогресс и подтверждённое переключение.

В браузере на локальном сервере:
1. Установлена старая сборка 9729b09070a1db1b.
2. Ручной переход на ce76a01b182fd91c: 757 ресурсов использованы из старой копии, 4 изменённых загружены (40 601 байт содержимого). Отдельно получены SW и манифест. Шесть увеличений на первом просмотре новой карточки загружались по запросу, а не как часть обязательного обновления.
3. Искусственная CSS-правка: 760 ресурсов использованы повторно, загружен один CSS (16 377 байт), без PDF, малых изображений и уже просмотренных увеличений. Журнал HTTP подтверждает только CSS, манифест и проверки SW.
4. Временно недоступный sw.js: показана ошибка, обе кнопки снова доступны, сохранённая карточка работает. После восстановления повтор по Enter успешно переключает версию.
5. Две открытые карточки получили новый контроллер. Повторная проверка завершилась сообщением «Установлена актуальная версия.».

В ходе просмотра исправлен старый дефект hover: на тёмной шапке каталога текст кнопки сохраняет светлый цвет.

Браузерная проверка выполнена при фактической ширине документа 1265 px. API изменения viewport в этой сессии не применил запрошенные 320 px: мобильная проверка этого изменения не заявляется. Сохранились прежние адаптивные правила и ResizeObserver высоты мобильной панели. Работа с отсутствующей сетью, ошибками места и тайм-аутами проверена моделями тестов; физическое отключение сети в браузере не выполнялось. Снимки: .impeccable/review/offline-update-desktop.jpg и offline-update-error-desktop.jpg.

Миграция со старого формата один раз читает и проверяет сохранённые файлы локально; дальнейшие обновления используют готовые хеши. После очистки данных браузера необходима обычная полная первая загрузка.

## Основания

Жизненный цикл, ожидание готовности и явная активация следуют [документации Chrome о Service Worker](https://web.dev/articles/service-worker-lifecycle) и [MDN: skipWaiting](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope/skipWaiting). Повторное использование файлов и возобновление относятся к реализации проекта, а не к автоматическому поведению браузера.
