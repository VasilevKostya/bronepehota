# Бронепехота — Уральская версия

Полевой справочник правил для телефона и компьютера. Первая редакция — **0.1**, 8 ноября 2026 года.

Сайт: **https://vasilevkostya.github.io/bronepehota/**. Первая публикация — 8 ноября 2026 года. Статус и ограничения проверки фиксируются в PRODUCT.md.

## Что входит

- Десять глав с оглавлением и прямыми ссылками на пункты.
- Поиск по правилам, таблицам и подписям иллюстраций: русские словоформы, е/ё, сокращения и небольшие опечатки.
- Полная офлайн-копия: главы, шрифты, картинки, поисковый индекс и PDF. Дождитесь статуса «Доступно без интернета» при первом посещении.
- PDF A4 с оглавлением, закладками, таблицами и иллюстрациями.
- Заглушка армлистов; наполнение этого раздела отложено.

Новая редакция скачивается целиком и проверяется по SHA-256 каждого файла. Прерванная загрузка сохраняет предыдущую копию. Переключение происходит после нажатия «Обновить». Офлайн-данные относятся к конкретному браузеру и могут быть удалены его настройками хранения.

## Локальная сборка

Нужны **Python 3.12+** и **Node.js 22+**. В браузере нет зависимостей от серверного API, внешних шрифтов или CDN. JavaScript-библиотеки устанавливать не требуется.

```sh
python -m pip install -r requirements.txt
python scripts/build.py
node --test tests/*.test.mjs
python scripts/verify.py
node scripts/serve.mjs --host 127.0.0.1 --port 4173
```

На Windows вместо `python` можно использовать `py -3.12`. Предпросмотр: `http://127.0.0.1:4173/bronepehota/`. Готовая статическая сборка лежит в `dist/`, PDF — `dist/bronepehota-ural-0.1.pdf`. Открытие HTML через `file://` не поддерживает поиск и service worker: используйте локальный HTTP-сервер.

## Как редактировать правила

1. Меняйте главы в `content/rules/*.json`. Блоки: абзац `p`, пункт `bullet`, `table`, `figure`, редакционное примечание `note`. Идентификатор раздела — постоянная ссылка; сохраняйте его при редактуре заголовка.
2. Изменяйте номер, дату и список изменений в `content/release.json`.
3. Обновляйте `content/source-audit.json`, если исправляете исходные опечатки или переносы. Механику изменяйте только после согласования.
4. Соберите и проверьте сайт командами выше. Текст сайта, PDF и поиска генерируется из этих JSON, независимо править результаты сборки не нужно.

Исходник — предоставленный `Pravila_turnir (1).docx`, фанатская пробная редакция 2025 года. Его SHA-256, перечень исправлений и привязки к исходным абзацам находятся в `content/source-audit.json`. Исходный DOCX не нужен для повторной сборки. Скрипты `inspect_source.py` и `import_rules.py` служат для аудита первоначального переноса; повторный импорт перезапишет ручную редактуру и требует явного флага.

Неоднозначные места отмечены «Требует уточнения» на обеих поверхностях. Эти примечания не вводят новую механику. Содержание исходных изображений дополнено текстовыми таблицами и подписями; оригинальные иллюстрации сохранены.

## Дизайн

Единственный брендбук — [DESIGN.md](DESIGN.md). В нём фиксируются фактические цвета, шрифты, размеры, состояния, адаптивность, движения и PDF. Обновляйте его в одной правке с визуальными изменениями, а композицию экрана — также в `docs/design/`. Выбранный пользователем эталон: «Полевой справочник», первый вариант первой тройки.

Шрифты PT Sans/PT Sans Narrow и пиктограммы Phosphor поставляются локально. Лицензии сторонних ресурсов лежат в `assets/licenses/`; происхождение игровых иллюстраций — в `docs/content-audit.md`. Публичное размещение само по себе не задаёт отдельную лицензию для игровых материалов.

## Публикация

Для репозитория `VasilevKostya/bronepehota` установите **Settings → Pages → Source: GitHub Actions**. Workflow `.github/workflows/pages.yml` собирает PDF и сайт, выполняет проверки и публикует `dist/` при изменениях ветки `main`. После развёртывания `scripts/verify_deployed.py` проверяет публичный адрес, service worker и SHA-256 всех 94 ресурсов из манифеста редакции, включая PDF. При несовпадении версии или файла workflow завершается ошибкой. Для ручного запуска доступен `workflow_dispatch`. Источник публикации — GitHub Actions, ветка с готовым HTML не требуется.

Все ссылки относительные и работают внутри `/bronepehota/`. Токены и секреты в проекте не нужны: публикация использует стандартный `GITHUB_TOKEN` рабочего процесса.
